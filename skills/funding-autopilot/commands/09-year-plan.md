# /year-plan — Turn ongoing grant readiness into a 12-month research plan

Use the user's uploaded-CV profile, their confirmed career dates/goals and the **actual source-checked calls** in private/ledger.json. This is a one-time, AI-authored planning document, **not** a scheduler or automatic background monitoring. Read [year-round strategy](../../../docs/YEAR-ROUND-READINESS.md), [global discovery](../references/discovery.md), and [proposal strategies](../../../docs/PROPOSAL-STRATEGIES.md).

1. **Scope.** Ask at most one consequential missing fact if truly necessary: the preferred starting month. If absent, use the user's current local month and clearly label it. User geography, salary, independent-vs-new-PI and research goals come from the private profile; do not request a second CV.
2. **Collect evidence.** Read the private CV fact ledger, degree milestone plans vs actual dates, verified funding rounds and actual funder and host deadlines (including timezone). If a deadline is unknown, say "not yet verified" — do not invent a date from an annual trend or another year's call.
3. **Lay out 12 calendar months.** Maintain overlapping tracks: profile + research evidence; global source radar + eligibility; prospective hosts and PI conversations; substantive /prepare evidence and experimental work; application drafting and reviewer repair; submission receipts and outcome learning. Explain capacity and dependencies. Not every activity starts or ends in the image's illustrative month.
4. **Build 2–3 viable tracks**, if evidence supports them: independent fellowship with PhD timing, a new-PI/Host project grant, and optional industry/collaborative/impact path. Preserve real differences in scheme-specific writing.
5. **Plan backwards from actual deadlines.** Place required internal sign-off and final files ahead of the funder's cutoff, with provisional lead time only when explicitly labeled as a recommendation. Avoid month 6/10 hard deadlines unless the official call really has them.
6. **Write private/annual-plan.md** with a month-by-month table `month | evidence/research tasks | funding/PI tasks | deliverable | actual scheme deadline or unknown | blocker`. Include a "Source and checked-at" section and a "Review and update triggers" section. Also offer optional 12-month project-specific outlines in private/; never write applicant details to a public repo.
7. **Report completion accurately.** Created a plan, not a scheduled recurring search. If the user separately asks for reminders/monitoring, use an actual authorized host scheduler if available, independent of Github Actions. Applicant messages and submissions still require approval.

The static timeline in the public README is a visual *example*, not a live individualized schedule or a calendar invite.
