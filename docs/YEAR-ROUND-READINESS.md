# A 12-month rolling funding readiness system

A month-by-month planning *template* for researchers. It is intentionally relative (M01–M12) and **does not assert actual deadlines** for any funder. The applicant's actual CV, target institution, time zone, source-checked funding calls and internal administrative cutoffs govern real scheduling.

![Rolling 12-month example across overlapping funding workstreams](../assets/yearly-roadmap.svg)

## Working rhythm

| Relative months | Focus | Checkable output |
| --- | --- | --- |
| M01–M02 | Confirm CV facts, expected and actual degree milestones, research goals, target countries and feasible PI/Host paths | User-reviewed private research profile; known evidence/skill gaps |
| M01–M12 | Search official funding sources regularly **when the agent is actually invoked**, record live round/version/deadline, assess changing eligibility | Source-cited, deduplicated and revisited funding opportunities; explicit source coverage gaps |
| M02–M05 | Compare potential independent fellowships to new-PI grants; contact only with user approval; check Host departments and internal deadlines | PI/Host shortlisting and unresolved commitments |
| M03–M08 | Develop a robust scientific problem, closest baselines, actual feasibility/resources, deliverable work packages, budget and letter requirements | Applicant-reviewed `preparation.json` per selected call |
| M05–M11 | Convert an approved strategy into a funder-specific draft; scientific and compliance red-team review; format and assemble annexes | Versions of drafts with source-linked claims and known missing materials |
| M07–M12 | Record real portal submissions and decisions, failure reasons and resubmission knowledge | Source receipts, feedback and updated next-cycle research plan |

These windows intentionally overlap and may repeat. Most grant cycles differ, some are rolling, and internal dates may close earlier than official funder dates. **Do not trust illustrative submission "waves" in a chart as deadlines.**

## How to personalize /year-plan

A host-aware agent with access to the project can read the private uploaded-CV profile and private funding ledger, then build `private/annual-plan.md`. For each month record:
1. The research evidence to strengthen (actual papers, experiments or reproducible proposals).
2. Official schemes and national/host requirements to recheck with timestamped sources.
3. Which PI/Host, salary and mentoring questions remain unresolved.
4. A specific `/prepare` or `/apply` deliverable and reviewer assignment.
5. Known applicable funder/department deadlines and required institutional lead time.
6. The next decision based on source evidence or negative outcomes.

Personal data remain inside `private/`. A one-time yearly plan is **not a service or background scheduler**. Actual reminders or repeated research need a separately installed and authorized host task capability, not GitHub Actions or Skill text alone.
